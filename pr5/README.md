# ПР5. Семантичний пошук у колекції документів

Система семантичного та ключового (BM25) пошуку по базі знань магазину електроніки «Сузірʼя».

## 2. Швидкий старт

### Крок 1. Створення та активація віртуального середовища

**Windows (PowerShell):**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**macOS / Linux:**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Крок 2. Встановлення залежностей

```bash
pip install -r requirements.txt
```

### Крок 3. Налаштування середовища

```powershell
copy .env.example .env     # Windows
# cp .env.example .env      # macOS / Linux
```

### Крок 4. Побудова пошукового індексу

Індекс будується заздалегідь перед запуском веб-застосунку:

```bash
python scripts/build_index.py
```
*(або `python ingest.py`)*

Скрипт розібʼє 16 документів на 136 змістовних фрагментів, згенерує вектори моделлю `intfloat/multilingual-e5-small` і збереже їх у `index/vectors.npy` та `index/chunks.json`.

### Крок 5. Запуск веб-застосунку

```bash
uvicorn app.main:app --reload
```

Відкрийте у браузері: **http://127.0.0.1:8000**

Застосунок працює у режимах `both` (показує обидва способи поруч), `semantic` або `keyword`. Підтримує фільтри за `category`, `product`, `audience`, `status`, а також налаштування `top_k` та `threshold`.

### Крок 6. Оцінювання якості пошуку (Evaluation)

```bash
python scripts/evaluate_search.py
```

Скрипт прожене тестовий набір із 15 запитів різної природи й розрахує метрики **Hit@1** та **Hit@3** для обох методів.

## 3. Теоретичні засади

### Що таке Embedding (ембедінг)?
Ембедінг — це щільне числове векторне представлення тексту у багатовимірному просторі (у моделі `multilingual-e5-small` розмірність дорівнює 384). На відміну від простого підрахунку слів, ембедінги фіксують **семантичний зміст** речення. Тексти зі схожим змістом (наприклад, «як повернути гроші» та «відшкодування вартості покупки») розташовуються близько один до одного у векторному просторі, навіть якщо не містять жодного спільного слова.

### Що таке Cosine Similarity (косинусна схожість)?
Косинусна схожість оцінює косинус кута між двома векторами $A$ та $B$:
$$\text{similarity} = \cos(\theta) = \frac{A \cdot B}{\|A\| \|B\|}$$
Значення лежить у діапазоні $[-1, 1]$ (для нормалізованих текстів — переважно $[0, 1]$). Якщо попередньо нормалізувати вектори до одиничної довжини ($\|A\| = 1$), то косинусна схожість дорівнює звичайному скалярному добутку (dot product):
$$\text{similarity} = A \cdot B = \sum_{i} A_i B_i$$
Це дозволяє розраховувати схожість для всієї колекції за частки мілісекунди через швидку матричну операцію `scores = vectors @ query_vector` у NumPy без потреби у сторонніх складних векторних БД.

### Навіщо потрібні Chunks (фрагменти)?
Документи бази знань можуть містити тисячі слів і охоплювати багато різних тем (наприклад, інструкція до навушників описує комплект, заряджання, підключення Bluetooth та скидання налаштувань). Якщо закодувати весь документ одним вектором, специфічні деталі «розмиються» в усередненому векторі документа. Крім того, моделі ембедінгів мають ліміт на довжину вхідного контексту (`max_seq_length` = 512 токенів). Поділ документа на невеликі фрагменти (chunks) фіксує кожну окрему думку в самостійному векторі та дозволяє показати користувачеві саме той абзац, який відповідає на його питання.

### Що таке BM25?
BM25 (Best Matching 25) — класичний алгоритм ранжування для інформаційного пошуку на основі частотності слів. Він удосконалює TF-IDF, враховуючи нелінійне насичення частоти терміна (TF) та штрафуючи занадто довгі документи (довжину тексту відносно середньої довжини у колекції). BM25 ідеально підходить для пошуку точних артикулів (наприклад, `OR-X2-BLK`), номерів замовлень, кодів помилок (`помилка E3`), але не розуміє синонімів, описок чи перефразувань.

### Чому індекс зберігається на диску?
Обчислення ембедінгів вимагає прогону текстів через нейромережу, що займає відчутний час (близько 10–20 секунд на CPU для колекції). Якщо рахувати вектори під час кожного старту застосунку, запуск був би надто повільним і споживав би ресурси. Збереження готових векторів у бінарному файлі `vectors.npy` та фрагментів у `chunks.json` дозволяє веб-серверу завантажитися за кілька мілісекунд (`np.load`).

### Чому не можна змінювати embedding model без перестроювання індексу?
Кожна модель ембедінгів навчається власному простору представлень: її координати, розмірність (наприклад, 384 у `e5-small` проти 768 у `e5-base` чи 1536 в `text-embedding-3-small`) та геометрія семантичного простору є унікальними. Порівнювати вектор запиту від однієї моделі з векторами документів іншої моделі математично безглуздо — це як порівнювати координати на мапі Києва з мапою Парижа. При зміні моделі в `.env` система перевіряє сумісність і вимагає повторного запуску `python scripts/build_index.py`.

## 4. Результати тестування (Baseline vs Experiment)

Детальний аналіз наведено у [`compare/results.md`](file:///C:/Застосунки_З_ШІ/pr5/compare/results.md).

- **Семантичний пошук (multilingual-e5-small)**:
  - Hit@1: **42.9%** (6/14)
  - Hit@3: **85.7%** (12/14)
  - Відмінні результати на синонімах, перефразуванні та опечатках.
- **BM25**:
  - Hit@1: **57.1%** (8/14)
  - Hit@3: **64.3%** (9/14)
  - Висока точність на точних кодах та артикулах, але відсутність гнучкості на описках та синонімах.
- **Експеримент з префіксами E5**: вимкнення обовʼязкових префіксів `query: ` / `passage: ` призвело до суттєвого падіння Hit@3 з **85.7% до 71.4%**, що підтверджує важливість дотримання специфікації моделі.
